# 智能简历排版助手

把一份 Markdown 写成的简历，实时排版成 A4 纸面，直接导出 PDF / 图片的本地小工具。

面向没设计背景的求职者：左边写内容、右边实时看效果，四种主题一键切换，页尺实时标出内容排到哪里、有没有超出一页。

**项目名**：简历管理。网页工具：既可以双击单文件 HTML 离线使用，也可以部署成在线网页；不做成 DSH 插件。

**当前状态**：可用版本，已打包成单文件 HTML；社媒、页数、外壳、章节、版本、分栏、品牌图标、照片压缩、导出文件名、排版微调共 10 组校验脚本（`cd app && npm test`），其余交互仍靠手测。

## 核心功能

- **左写右看**：左栏编辑字段与 Markdown 正文，右栏 A4 纸面实时预览（面板可拖拽调宽，纸面等比缩放不裁切）；左栏内部还能上下分栏——拖动基本信息区下沿的细线，把下面的 Markdown 编辑区拉大，填完基本信息就往上收；高度会被记住，双击细线复位
- **页尺**：纸面左侧标出 0 / 25% / 50% / 75% / 1 页，内容排到哪里一目了然；超出一页的那段用砖红画出来，右下角状态栏显示精确占比
- **两档外壳**：工具界面配色可切换——深海军蓝（默认）/ 暖米，顶栏右上角的**月亮 / 太阳**一键切换，选择会记住；**外壳只影响工具界面，简历纸面永远是白纸黑字**
- **四种主题**：极简风格 / 商务正式（藏青页眉 + 古金压线）/ 互联网风 / 学术经典（居中发丝线 + 中文序号分节）
- **排版微调**：顶栏「排版」按钮在顶栏下方展开一整行工具条（占文档流、把工作区往下推，不盖住纸面），对整份简历做五项微调——字号、行距、照片尺寸、**页边距**（各按档位 ±，显示百分比）、字体（主题默认 / 现代黑体 / 经典宋体 / 人文楷体，用电脑自带字体、不联网）；照片可放大到 200%，页边距可收到 70%，方便把内容收进一页。默认全是 100% / 主题默认，即现状，商务正式的默认表现不变；点纸面调参数时工具条不会误收起，按 Esc 或点右侧 × 收起，改过会记住，可单项「默认」或「全部复位」；字号、行距、页边距、照片改动后页数会变，页尺实时显示
- **字段 + 正文**：姓名、意向岗位、电话、邮箱、一句话定位、照片（本地选择，转 base64 内嵌；选图时自动压到长边 600px、约 100KB，避免一张手机照片吃掉浏览器配额），正文用 Markdown
- **社媒栏**：公众号 / 小红书 / GitHub / 个人网站四项，纸面上与联系方式同排展示；公众号、小红书带平台 logo（内联 SVG，离线可用），GitHub 自动归一成 `github.com/用户名`；小红书显示账号名，填了主页链接后可与 GitHub、个人网站一起在导出的 PDF 里点开（PNG 是位图，不能点）；个人网站去掉 `https://` 与末尾斜杠只显示域名。默认预填一组示例账号（示例公众号 / 示例小红书 / `github.com/example` / `example.com`），可随时改
- **三种导出**：存图（下载 PNG）、复制图片到剪贴板、导出 PDF（走浏览器打印，打印对话框里选「存储为 PDF」）；顶栏实时显示预计页数，导出文件名自动为**导出当天的日期-姓名-岗位**（如 `2026.11.18-张三-高级前端工程师`），日期用点分隔、跟着你填的内容实时变，PDF 也用这个名字当默认名。顶栏每个动作按钮都带一个 13px 线性图标
- **版本存档**：顶栏「版本」按钮打开右侧抽屉，可为某个岗位的简历存一份快照（名字 + 时间 + 字数 + 主题），随时恢复、改名、删除；恢复时整份简历（Markdown 正文、基本信息、纸面主题）一起回来并**自动存盘**，不用再手点「保存」；恢复前你正在写的内容会先留一份「恢复前的草稿」；点任意导出前会自动留一份，内容没变则不重复存；支持导出 / 导入 JSON 备份
- **保存与续写**：点「保存」写入 localStorage（切换主题、外壳会即时保存）；在禁用 localStorage 的沙箱 iframe 里降级到宿主提供的持久化接口；写不进去（配额满）会明确报出来，不会假装「已保存」

## 设计取向

界面按「编辑社论」来做（参考 Signal Theme 的视觉语言），不是 SaaS 后台：

- **外壳两档**：深海军蓝 `#1c2644`（默认）与暖米 `#f0ece3`，两档共用同一套 CSS 变量，切外壳只换变量、不动组件
- **单一强调色**：古金 `#c8a870`（暖米外壳下压暗为 `#7d6130`），只用在字标方章、主按钮、激活页签、分节短线
- **纸面永远白纸黑字**：外壳色不进纸面，打印投 HR 时不会有底色，也不会出现「屏幕好看、打印发灰」
- **网格与直角**：工作区 80px 网格纹理，零圆角、零渐变、零阴影（纸面只用一层极淡投影与底色分开）
- **字体**：衬线（Georgia + 宋体）做字标与简历标题，系统黑体做界面正文，等宽字体承担数字与元信息（字数、页数、日期、页签罗马数字）；纸面字体可切换到几套常见组合（黑体 / 宋体 / 楷体 / 主题默认），但只用系统已装的字体，不内嵌字体文件
- **排版微调**：字号 / 行距 / 照片 / 页边距 / 字体五项都是「相对现状的倍数或档位」，默认即现状；实现上把四套主题里写死的 px 改成 `calc(Npx * var(--fs,1))`、纸面留白改成 `calc(Npx * var(--pad,1))` 这类 CSS 变量，变量缺省为 1 时逐字节等于改动前，保证默认视觉不变（尤其商务正式）；工具条在顶栏下方占一整行，不用浮层，避免挡住纸面
- **表单**：下划线填空 + 等宽小字标签在上，像稿纸；不用圆角卡片、emoji
- **页签图标**：深海军蓝方底 + 白纸 + 古金刊头。同时内联两份——SVG（认它的浏览器用矢量）+ 32×32 PNG（Safari 26 之前不认 SVG，靠它兜底）。图形只在 `app/make_favicon.py` 里定义一次，跑它重写 `index.html` 里两份 data URI
- **图标**：顶栏动作用 lucide 线性图标（13px、1.6 笔画）；外壳切换用太阳 / 月亮，不再用「深 / 暖」两个字；电话、邮箱在左栏字段标签和纸面简历头部各带一枚细线图标（`PhoneIcon` / `MailIcon`），四套主题通用
- **签名元素**：纸面左侧的页尺，全站只在这一处用警示色
- **改版时别退回旧风格**：不要再引入蓝紫渐变、pill 分栏、圆角浮层

## 技术栈

| 层 | 选型 |
| --- | --- |
| 前端 | React 19 + TypeScript 5.9 + Vite 7 |
| 样式 | Tailwind CSS 3.4 + CSS 变量驱动的外壳色板（`index.css` 的 `:root` / `[data-shell='light']`） |
| 图标 / 导出 | lucide-react、html-to-image |
| 打包 | `vite build` 后用 Python 脚本把 JS/CSS 内联进单个 HTML |

## 本地运行

```bash
cd app
npm install        # 首次
npm run dev        # 开发预览，默认 http://localhost:5173
npm test           # 社媒、页数、外壳、章节、版本、分栏、品牌图标、照片压缩、导出文件名、排版微调的校验脚本
```

## 构建与分发

```bash
cd app
npm run build             # tsc 类型检查 + vite 打包到 dist/
python3 inline_build.py   # 内联成单文件 HTML
```

`inline_build.py` 会生成仓库根目录的 `简历排版助手.html`（独立版，双击即可用，无需服务器）；同时会写一份 `app/widget.html` 供本机看板内嵌，不随仓库发布。

## 部署

线上版跑在阿里云香港的一台 ECS 上，用 Caddy 直接托管构建好的静态文件，不经过 Cloudflare Pages：

| 项 | 值 |
| --- | --- |
| 站点地址 | `https://jianli.weiyudubai.com` |
| 服务器目录 | `/var/www/jianli` |
| Web 服务器 | Caddy（`/etc/caddy/Caddyfile`，自动签发/续期 Let's Encrypt 证书） |
| DNS | 阿里云云解析 `A jianli → 47.83.177.108` |

更新线上版本（本机执行）：

```bash
cd app
npm ci
npm run build
rsync -avz --delete app/dist/ root@47.83.177.108:/var/www/jianli/
```

`git push` 只更新 GitHub 上的源码，不会自动部署；每次改完要手动跑上面的构建 + rsync。

简历数据只存在浏览器 localStorage，`file://`、线上域名、`localhost` 之间互不相通；换地址或换设备时，用「版本 → 导出备份 / 导入备份」迁移。

## 文档自检

```bash
python3 scripts/check_docs.py
```

检查仓库内 Markdown 的代码围栏是否配对、站内相对链接是否都能解析。改过任何 `.md` 都要跑一遍。
